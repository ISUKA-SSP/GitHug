# GitTotte v1.1.0 操作ガイド

## 最初は操作ガイドから

「＋ プロジェクト」でGitHubのURLを登録して保存先を選び、「操作ガイド」を開きます。目的を選ぶと、主画面で選ぶ場所を水色の枠で示します。選択済みの手順は省略し、通常の確認画面につなげます。ガイドを閉じても操作済みの内容は戻らず、進行中の処理は継続します。通常の確認画面が開いている場合は、その画面のキャンセルで戻れます。

## 履歴を取得・コピーする

「GitHubの履歴を更新」は、アプリ専用の履歴保管場所だけを更新します。PCの作業フォルダーには反映しません。

上の履歴を選び、下のPC欄の空白へドラッグすると、新しいフォルダーへコピーします。「この時点のファイルをPCへコピー」も同じ操作です。最新版は使いたい作業ルートの先頭を選んでください。別ルートの日時が新しいだけでは、使いたい版とは限りません。

同じフォルダーを更新したい場合は、履歴を下の対象の行へドラッグします。上書き更新が有効なフォルダーだけが対象です。登録した作業フォルダーの更新を有効にする操作は、右クリックで明示的に行います。作成元が不明なフォルダーは、そのまま更新しません。

更新画面で手元の変更を確認し、バックアップの有無と「手元だけのファイルを残す」を選びます。この設定がONでも、もとの履歴に含まれていたファイルへの編集は、選んだ版に置き換わります。設定・DBなどの手元だけのファイルは残す対象ですが、選んだ版と同じ保存場所で衝突する場合は止めて案内します。判断に迷う場合は新しいフォルダーへコピーしてください。

## PCだけに記録する・GitHubへ送る

PCのフォルダーを右クリックして「PCに記録だけ残す」を選ぶと、ファイルと説明・名前・メールを確認してPCだけに保存できます。GitHubへは送信しません。元のフォルダーを後で編集・削除しても、保存した記録は残ります。

下のフォルダーを上の履歴へドラッグすると、GitHubへの送信画面を開きます。ドラッグだけでは送信しません。送るファイル、送信先の作業ルート、変更の説明、名前とメールを確認します。ファイルのダブルクリックで対象を切り替えられます。削除を送信対象にすると、そのファイルを新しいGitHubの履歴から取り除きます。過去の履歴にある内容は残ります。

GitHub側にも更新がある場合は、ファイル全体をPC側／GitHub側のどちらに合わせるか、または保留するかを選びます。保留が残る間は送信しません。行ごとのコード編集・自動統合は行いません。別の作業ルートへ送ることもできます。送信は別の作業用コピーで準備し、送信元のファイルやGit管理情報を直接変更しません。

PCに保存した記録は「保管した内容 → PCの記録」で確認・送信できます。記録につながる以前の内容も送信に含まれる場合があるため、送信前の全体確認を読んでください。

## 比較・取り込み提案

上で履歴、下でPCのフォルダーを1つ選び、「比べる・取り込む → 作業フォルダーと比較」を開きます。未選択ならフォルダー選択画面を開き、複数選択なら1つに絞るよう案内します。比較は読み取りのみです。無視対象や改行形式の違いも含むため、大きなフォルダーでは時間がかかります。進行状況と中止ボタンがあります。

「別の作業ルートと比較・取り込み提案」では、変更を持ってくる「取り込み元」と、変更を受け取る「取り込み先」を選びます。差分を確認してGitHubを開けます。提案の作成・合流の確定はGitHub上で行います。ガイドの比較完了は、取り込みの完了ではありません。

## 記録・バックアップから復元

「保管した内容 → PCの記録／更新前のバックアップ」で項目を選び、「新しいフォルダーへ復元」を押します。ファイル数・サイズ・新しい保存場所を確認してから実行します。

- PCの記録：その記録に保存した変更と、もとのファイルを取り出します。記録対象外の手元だけのファイルは含みません。
- 更新前のバックアップ：ZIPにある設定・手元だけのファイル・空フォルダーも取り出します。
- 毎回別のフォルダーを作り、元のフォルダーや記録は変更しません。復元したコードを自動実行しません。
- 元のフォルダーの自分用メモを引き継ぎ、復元日時・出どころを一覧に残します。上書き更新はOFFから始まります。
- 復元先が削除・移動されている場合は、元の記録からもう一度新しいフォルダーへ復元できます。復元後に加えた未記録の編集は戻りません。

## 一覧・ファイル・メモ

履歴・PCのフォルダーを検索・並べ替えできます。自分用メモも検索対象です。履歴はページ切替に対応し、つながり順では分岐・合流をグラフで表示します。

PCのフォルダーはCtrl・Shiftで複数選択できます。右クリックからまとめてごみ箱へ移動したり、削除・移動済みの項目だけ一覧から取り除けます。確認画面で対象を読んでください。一覧から取り除いても、自分用メモは保持します。複数選択したフォルダーをまとめてドラッグ送信することはありません。

フォルダーを選ぶと左下のツリーに中身を表示します。ファイルは普段のアプリで編集します。右クリックからVS Codeでも開けます。標準位置以外の場合は検出や実行ファイルの指定を使えます。

## PowerShell／コマンド

PCのフォルダーを1つ選び「PowerShell／コマンド」を押すと、下側のパネルで操作できます。複数行のコマンドを入力して実行し、実行途中の質問には「途中の入力」から回答します。

- ✖：パネルを隠します。処理は続きます。
- 最新の出力へ：出力の末尾に戻ります。
- 処理を中断：Ctrl+Cを送ります。
- 終了：PowerShellと配下の処理を終了します。
- 開き直す：新しいセッションを始めます。

作業場所はセッション開始時のフォルダーに固定します。別のフォルダーを選んでも、実行中の処理の作業場所は勝手に変えません。任意のコマンドはファイルを変更・削除できるため、内容と場所を確認して実行してください。外部PowerShellで開く選択肢も残しています。

## 設定・互換性・制限

表示用語は「操作名／Git用語」をその場で切り替えられます。ホバー説明・選択時の案内・キャラクターの動きは設定からOFFにできます。

旧名GitHugからの互換性のため、設定は `%APPDATA%\GitHug\settings.json`、Python内部パッケージ名は `githug` のままです。新しいZIPを別の場所へ展開しても、既存の設定・メモ・登録先・資格情報を引き継ぎます。

非公開プロジェクトや送信にはPC側のGitHub認証と権限が必要です。公開プロジェクト用のGitは同梱しますが、認証設定が自動で済むものではありません。ChatGPTの接続設定も引き継ぎません。

submodule・Git LFSの実体取得や、Python実行環境の自動準備には対応していません。Geminiの説明は任意で、送信前に内容を確認してください。

## ソース・Windows版のビルド

Python 3.11以降（tkinterを含む）とGitが必要です。Windows配布版の検証にはPython 3.13を使っています。

```powershell
python -m pip install -r requirements.txt
python -m gittotte
python -m unittest discover -s tests -v
```

Windows上で配布版を作る場合：

```powershell
python -m pip install -r packaging/requirements-build.txt
python packaging/rebuild_bootloader.py
python packaging/build_windows.py
python packaging/verify_bundle.py dist/GitTotte build/windows-smoke.json
```

GitHub Actionsの「Build Windows portable」も利用できます。PyInstallerの通常のブートローダーを、固定した公式ソースとSHA-256を確認してビルドします。コード署名を付ける工程ではありません。[同梱ソフトウェアについて](../packaging/THIRD_PARTY_NOTICES.md)も参照してください。

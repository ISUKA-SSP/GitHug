# GitTotte 1.1.0a11：両方で変更されたファイルを選ぶ

- 既存の作業ルートに送信するとき、GitHub側にも別の更新があれば、選ぶ画面に進みます。通常の作業フォルダーと、保存済みのPCの記録からの送信に対応します。
- 共通の出発点・PC側・GitHub最新版の内容を比べます。同じファイルで両方が変更されていれば「保留」が既定です。
- ファイルごとに「PC側を使う／GitHub側を使う／保留」を選択。ファイル全体を選びます。行ごとの自動合成はしません。
- 削除も一方の状態として扱います。「PC側：なし／削除」でPC側を選べば、新しいGitHubの記録からそのファイルを取り除きます。PC側のファイルを削除する操作ではありません。
- 選んだファイルは左右の本文で確認し、共通だった内容も別に確認できます。バイナリ・大きいファイルは本文の代わりにその旨を案内。
- GitHub側だけの変更は残します。構成がファイルとフォルダーに分かれている場合やリンクなど、PC側へ安全に置き換えられないものはGitHub側／保留のみとし、別ルートへの送信を案内します。
- 保留が1件でもあれば確認・送信ボタンは無効。キャンセルすれば作業フォルダー・GitHubの履歴・保存済みのPCの記録に変更はありません。
- 全件を選んだ後も、GitHub最新版に対する最終差分を確認してから送信します。
- 解決結果はGitHub最新版を直接の親にした別のコミットとして送信。元のPCの記録自体を作り替えません。すでにPC側の履歴がそのまま送れる場合は従来どおり送信します。
- 実行直前のPC変更と送信先の更新を確認。送信中の更新にも参照の一致を条件にし、既存履歴を巻き戻しません。変更されていれば「確認をやり直す」から再比較します。
- GitHub側を選んだ内容をPCへ書き戻す処理はしません。PCの古い状態をGitHub最新版と誤認しないよう、元フォルダーの比較基準も勝手に進めません。
- 最終状態がGitHubと同じなら、新しいコミットや送信は作らず案内します。
- この段階は「既存ルートへの送信前」の対応です。ブラウザーで作成した取り込み提案のコンフリクトをアプリから直接編集する機能や、ダウンロード時の上書き画面の置換は含みません。

今回もPython版のみです。
